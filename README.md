# 泳者计划

一个减脂增肌的训练与饮食追踪器，跑在 Claude Artifact 里。手机打开，四个页签：训练、饮食、身体、计划。

它和一般的健身 app 不一样的地方：**计划是一个数据对象，不是写死的界面。** 你的基线、目标、周期安排、动作和起始重量全在一个叫 `plan` 的结构里，引擎读它干活。换一个人，就是换一份 `plan`。

## 它能干什么

**训练页** — 当天该练什么直接列出来，每个动作带示意图、发力感觉、常见错误、动作要领。填次数和「最后一组还能再做几次」，下次的重量 app 自己算。

**饮食页** — 拍照或一句话记一餐，AI 估算热量和三大营养素。当日还能吃多少、蛋白差多少，实时算。外食模式给你一套点菜规则。

**身体页** — 每天早上记体重，看 7 天均值和趋势带（不看单日跳动）。腰围每 4 周，体成分扫描每月，上传扫描单照片自动读数。

**计划页** — 24 周路线、日历、饮食阶梯、加重规则、教练备注。

## 三步开始

**1. 打开 [`GENERATE.md`](GENERATE.md)，整段贴给你自己的 Claude。**

**2. 回答它问的问题** —— 身高体重、体成分（有就给，没有它会估）、目标、每周能练几天、器械条件、伤病、饮食限制。

**3. Claude 生成你的 `plan` 并发布成你自己的 Artifact。** 链接归你，数据存在你自己的账号下。

## 为什么不是「打开链接就能用」

用了同步存储（`db`）的 Artifact **只能在组织内部分享，不能公开**。而且一份 Artifact 只有一个存储空间 —— 所有人打开同一个链接，数据会写进同一个地方，你的体重和别人的混在一起。

所以正确的用法是：**每个人生成自己的一份。** 你的数据在你的存储里，AI 估算走你自己的额度，谁也看不见谁的。

代价是多一步生成。好处是隔离干净，而且你可以随便改自己的计划，不用等我。

## 仓库里有什么

| 文件 | 是什么 |
|---|---|
| `src/index.html` | 框架本体，一个文件，可直接发布。里面的 `DEFAULT_PLAN` 是**虚构示例人**的数据 |
| `GENERATE.md` | 贴给 Claude 的生成指令 |
| `PLAN.schema.md` | `plan` 对象每个字段什么意思、怎么填 |
| `CHANGELOG.md` | 框架更新记录 |

## 示例人是谁

`src/index.html` 里那份是编的：185 lb / 23% 体脂 / 腰 92 cm，目标 165 lb / 15% / 腰 82 cm，24 周（起始日 2026-09-01）。用来展示界面长什么样，**不要直接拿来练**。

## 更新

我改框架就往这里 push。你想要新版本，重新走一次 `GENERATE.md`，把你已有的 `plan` 给 Claude 让它迁移到新模板 —— 你的历史记录在你自己的存储里，不受影响。

## 这不是医疗建议

我不是医生也不是持证教练。这里面的训练安排、热量和蛋白目标是给一个具体的人做的方案模板，不是对你的处方。有伤病、慢性病、在服药、怀孕，或者体重体脂在极端区间，先去问医生。练之前自己判断，出事我不负责。
